# Collector Operations visual system

Collector keeps its recognizable blue identity inside a neutral, work-focused interface. Use clear hierarchy, compact controls, thin borders, and restrained depth so operational data stays easy to scan.

Design tokens live in `frontend/src/styles/tokens.css` and map to Tailwind and shadcn variables in `frontend/src/App.css`. The light interface uses a cool neutral workspace, white surfaces, indigo actions, and semantic success, warning, information, review, and danger colors. Use 14px body text, 13px data, 12px metadata, 16px card titles, 25px page titles, and 23px metric values. Meaningful secondary text uses the muted token. Spacing follows 4/8/12/16/24/32/40px. Controls use 6px radii, panels 10–12px, and dialogs 12px. Shadows belong mainly to overlays. Lucide icons use 16px/18px and a consistent stroke weight.

The dashboard and management screens use a 248px sidebar, a 56px sticky top bar, and one page header with context actions. Their workspace content uses a 1680px maximum width. Dashboard summaries use responsive data-backed metric cards, never illustrative values. Button, Card, and Table primitives provide the shared presentation foundation. Tables use left-aligned text, right-aligned numbers and actions, readable 42px headers, compact 52px rows, and contained horizontal scrolling when needed. Investigation records use tables on desktop and compact lists on phones.

Status and priority colors describe their actual meaning: pending and cancelled are neutral; assigned and in progress are blue; under review is violet; returned for correction and high priority are amber; completed and approved are green; urgent priority is red. Account availability and account activation remain separate concepts. Badges keep text labels so color is never the only signal.

Investigation creation retains its five validated steps. Reports remains a review queue linked to investigation details. Field Agents keeps accounts, shifts, and assigned work visibly separate. Agent dashboards put route and correction work ahead of recent records. Investigation details identify the subject and reference first, then group location, assignment, schedule, status, and activity information.

Route Planning and My Route retain their existing shell, map, controls, panels, and responsive behavior. Route Planning uses a 304px investigation and agent roster, a flexible Leaflet map, and a 344px route inspector at wide desktop sizes. At 1200–1439px, route details move into a drawer. Tablets use mutually exclusive drawers; phones use Records, Map, and Routes tabs. Map data always has a list equivalent. Full-person markers indicate configured shift starting points; investigation pins are distinct. Only persisted assignments and validated published road routes appear as assigned, and H3 is labeled as density only.

Controls need visible focus, explicit labels, non-color-only status text, specific errors, and meaningful loading and empty states. Dialogs preserve focus. Mobile controls are at least 44px. Motion is short and functional; recurring menus do not animate and reduced motion is respected.
